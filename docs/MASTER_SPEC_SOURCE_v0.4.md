# 디지몬 챔피언십 개인용 웹 확장판 — Codex 통합 개발 명세 v0.4
작성일: 2026-10-26
상태: **원작 검증·설계 충돌 정리본 / 기획 누적 초안** (아직 구현 완료를 뜻하지 않음). 이후 대화의 확정사항을 이 문서에 계속 병합한다.

## 0. 최상위 목적, 우선순위
- 사용자가 직접 즐길 비공개 개인용 PC/Android 브라우저 게임. NDS 《디지몬 챔피언십》의 육성·포획·대회·진화 재미를 재현하되 반복 작업은 완화하고 살아 있는 사육장을 확장한다.
- **사용자가 명시적으로 확정한 확장판 변경은 최우선**, 변경하지 않은 부분은 ROM으로 검증한 원작 동작을 우선한다. 그다음은 영상 관찰, 위키 참고, 임시 수치 순으로 신뢰한다. 출처 신뢰도와 구현 우선순위를 혼동하지 말 것.
- 데이터 출처를 `rom_verified`, `video_observed`, `community_wiki_unverified`, `user_design`, `temporary_balance` 등으로 기록. 위키 자료는 유용한 검증 단서이지 ROM 해독 증거가 아니다.
- 기존 v0.14 HTML/사이트는 프로토타입. 기존 장기 작업지시서의 **가로 직선 복도/방 구매 중심 설계는 폐기·대체**하고 본 명세의 육각형 사육장 설계를 우선한다. 다른 정상 동작 기능은 회귀시키지 않는다.
- 확인 못 한 공식·오프셋·우선순위를 원작 확정이라고 주장하지 말 것. 반대로 데이터 미해독을 데이터 부재로 단정하지 말 것.


## 0.1 이번 v0.4 검토 결과 — 반드시 구분할 세 층
1. **원작으로 유지:** 케이지의 상·하락 트레이드오프와 랜덤 후보, 개체별 G, 수명/진화/디지에그/로스트, 랭크·타이틀 진행, 사냥 도구, 성격, 시간표, 배틀 기본 AI. 위키 내용은 ROM 검증 전까지 `community_wiki_unverified`.
2. **사용자 승인 확장 변경:** 원작의 일자 2열 케이지를 **콤팩트한 육각형 1개→여러 육각형 연결**로 재설계; 드래그 강제 대신 선택→시설/훈련 메뉴; 한 번 배치 후 **지속 훈련**; 자동 휴식/복귀 옵션; 미니게임 선택 및 최고등급 스킵; 진화 힌트/상세 정보 전환; 원작 캠페인 완료 후 확장 리그.
3. **아직 정하지 않은 것:** 보관소에서 나이/상태가 정지하는지, 200G가 초기값인지 최종 상한인지, 육각형마다 G가 증가하는지, 관계 보너스의 수치, 정확한 훈련 틱/HP 소모/능력치 변화, 진화 기억의 판정 순서, 전투 직접 조작의 구현 범위. 확정처럼 구현 금지.

## 0.2 중요한 수정·삭제 사항
- 예전 설계의 **'초기 3마리 고정'**, **'보관소 시간 정지 확정'**, **'진화하면 무조건 알'**, **'훈련은 스탯 상승만'**, **'전투는 직접 조작 불가능'**, **'시설은 복도에 방을 사서 붙임'**은 폐기 또는 미결정으로 강등.
- 위키의 '200G 최대'와 '테이머 랭크 상승 시 최대 용량 증가'는 모순이 아니라 **200G가 최종 상한일 가능성**도 있음. 랭크별 표 확인 전 수치 하드코딩 금지.
- 위키의 '4칸 기본 케이지'는 **원작 레이아웃 정보**이며 확장판의 '육각형 하나'와 일대일 대응 아님. 기능(기본 수령/생활 공간)만 재해석.
- 위키의 '진화는 조건 중 2개 정도 충족'은 **모든 진화에 공통으로 2조건 필요하다는 공식이 아님**. 종별 조건 표현식 그대로 파싱할 것.
- '시간 경과 진화'는 수명 종료 시의 진화/디지에그/로스트와 판정 단계가 다를 수 있음. 진화 가능 시각, 타이머, 우선순위 확인 전 합치지 말 것.
- 위키의 '능력치 AP=내성' 표기는 약어 해석이 불명확함. HP/TP/AP, 저항 5종, 종족 육성 수치, 백신·바이러스·데이터 속성은 **서로 다른 데이터 축**으로 설계하고 ROM으로 확인.
- [21], [22]는 앞 문맥이 없어 사실상 연결되지 않은 주석. 특정 개체에 무리하게 연결하지 말 것.
- 개인용 게임이더라도 ROM·스프라이트·음악의 **저작권/배포 권한이 생기는 것은 아님**. 자산은 사용자 소유 로컬 입력을 참조하고 저장소에 ROM 원본·저작권 자산을 무단 공개하지 말 것.

## 2. 확정된 플레이 방향
### 2.1 게임 전체
- 원작 기반 + 생활 시뮬레이션 강화. 시작은 디지타마 1개. 성장/진화는 조건과 시간에 따른 자동 판정, 결과 직접 선택하지 않음.
- 일시정지, 1x/2x/4x 배속. 하나의 게임 시계로 이동·훈련·회복·진화·배고픔·포획 이벤트 동기화. 초기에는 오프라인 진행 없음.
- 디지몬이 독립적으로 이동, 휴식, 놀이, 식사, 가까이 다가가기 등 반자율 행동. 플레이어가 먹이 배치, 훈련 지정, 시설 건설, 포획, 대회 출전을 결정. 기본 관계 시스템: 친밀도, 함께 놀기, 먹이 선점, 공동 훈련의 작은 보너스(세부값 미확정).
- NDS 2화면 외형 토글 + PC/모바일 확장 레이아웃. 레이아웃 전환은 동일 상태를 보여주며 시뮬레이션 리셋 금지.

### 2.2 사육장 지도: **A로 시작해서 C로 확장**
- 최초에는 **콤팩트한 육각형 사육장 하나**, 가운데를 디지몬 공용 생활 영역으로, 변/모서리 쪽을 **복수의 시설 배치 슬롯**으로 사용. 시작 사육장만으로 먹이·회복·기초 공격/방어·진화 관련 모든 기본 훈련을 가능하게 할 것(초기 설치 시설, 슬롯 및 기본 접근 정책은 밸런스 설계 필요).
- 테이머 랭크, 대회 타이틀 및 업적/Bit로 새로운 슬롯/시설을 해금하고, 성장 단계에서 **별도의 육각형 사육장 여러 개를 연결**한다. 처음부터 방대한 빈 지도를 보여주지 않는다. 여러 육각형 간에 자연스러운 이동 동선을 제공하되 과도한 이동시간과 작은 스프라이트 문제 방지.
- 해금과 설치는 다름: 플레이어가 해금한 구역에 원하는 시설을 직접 배치/교체/강화. 원작처럼 시설 계열·개별 시설에 테이머 랭크/타이틀 조건 부여.
- **위키의 원작**은 고정 기본 케이지 4칸, 가로 확장 5→랭크 상승 시 8칸, 케이지별 수용수 등으로 서술됨. **웹판의 단일 육각형→다중 육각형 방식은 의도된 변경**. 그러나 케이지 효과·가격·등급·디지몬 용량 제한을 추출하여 시스템적으로 계승.
- 보관소/대기 디지몬 기능 포함(A+C 합의). 사육장에 활동 배치된 디지몬과 보관소 개체를 구분. 보관소에서 상태·노화 정지 여부는 **이전 임시 제안으로 아직 원작과 충돌 검토 필요**, 기본값으로 확정하지 말 것. 보관소와 200G 용량 제한의 관계도 별도 결정 필요.

### 2.3 훈련 입력 및 연출: 수동 강요 금지
- **기본:** 디지몬 클릭/터치 → 시설 직접 클릭 **또는** 훈련 메뉴에서 능력치 종류 선택 → 이용 가능한 시설 자동 탐색 → 실제로 걸어가 시설에 들어감.
- 원작의 손 모양 도구로 직접 집어 들고 드래그하는 기능은 **선택적 대체 조작**. 모바일 터치와 마우스 모두 동작.
- 원작에서는 넣을 때 한 번 훈련 애니메이션과 결과가 나오며 꺼냈다 다시 넣어야 빠른 반복 가능하다는 사용자 증언. **확장판 의도적 변경:** 한 번 배치하면 기구 내에서 훈련 모션을 자동 반복, 모션 한 사이클 완료 시 HP 소모와 능력치 소폭 변동을 원자적으로 처리. 꺼내기/명령 취소 시 중단.
- 훈련 시설별 일부 능력치는 상승, **다른 능력치는 하락할 수 있다는 위키 핵심 규칙을 보존**. 원작의 랜덤 상승/하락 후보 중 무엇이 한 사이클에 적용되는지 검증 전에는 모든 후보를 동시에 적용하지 말 것. 앞서 ‘상승만’으로 서술한 문구는 교체. 실제 데이터는 ROM/영상 확인 우선.
- 훈련 중단 기준: 기본 최대 HP의 20% 내외를 **임시 안전값**으로 하고 다음 사이클 HP 소모 예측에 따라 조기 종료. 피로, 질병, 수면, 공간 점유, 시설 충돌 등 체크.
- 디지몬별 옵션: 일정 HP 회복 후 훈련 재개, 반복 예약, 행동 우선순위(위급 상태/식사/훈련). 자동 휴식 복귀는 **켜기/끄기 가능**.
- 짧은 선택적 미니게임(약 3~8초), C/B/A/S 등급 기록. 한 번 달성한 최고 등급을 같은 훈련에 재사용해 미니게임 스킵 가능. **스킵은 미니게임만**, 실제 훈련 시간/애니메이션·HP 변화 스킵 금지. 계정/세이브 내 훈련 종류별 최고등급 저장. 미니게임 없이 기본 등급 자동 훈련 가능.
- 상위 테이머 랭크에서 더 좋은 훈련 케이지/강화 단계 개방. 상위 등급일수록 수치 상승 외에 하락 페널티도 커질 수 있다는 위키 내용 검증·균형 조정. 초반의 **한 육각형 안에서 기본 육성 루프를 완결**할 것. 다만 원작 랭크로 잠긴 고급 시설이나 모든 종족 특화 시설을 시작부터 무료 제공하라는 뜻은 아님. 기본 시설·구매 가능한 저급 시설·교체 슬롯을 이용해 접근성을 확보.

### 2.4 먹이, 휴식, 사회성
- 먹이를 클릭만으로 수치 반영하지 말 것. 도구로 사육장 바닥 좌표에 놓고 아이템 객체 생성 → 배고픈 디지몬이 접근 → 먹기 GIF → 포만감 적용. 먹이는 방치 시 부패할 수 있으며 부패 섭취/발병은 진화 조건으로 쓰이므로 관련 카운터 추적.
- 수면/의료/온천 케이지로 HP 회복·스트레스 감소. 상점과 랭크 해금에 따라 자동 먹이 주기/배설물 청소 등 편의 시설 추가.
- 개체마다 선호/비선호 케이지 존재 가능성은 **커뮤니티의 미검증 기술**이므로 확실히 확인하거나 확장 규칙으로 명시.
- 관계 기본형만 확정. 심층 성격 궁합 등은 후순위. 그러나 원작 성격별 전투/육성 영향은 독립 구현 대상으로 유지(§3.4).

### 2.5 진화, 디지에그, 수명
- ROM/위키 진화 조건 최대한 복원: 종족별 육성 값(용, 짐승, 기계, 벌레풀, 성, 암흑, 새, 물 등), 배틀 누적, **배틀 승률**, 디지에그화 횟수, 질병/페널티 횟수, 시간 경과, 타이틀/테이머 등급, 용량 제약.
- 진화 조건의 AND/OR 조합과 **여러 후보 동시 충족 시 우선순위**는 ROM 분석 과제. 이전 예시(우드몬/에어드라몬/엔젤몬/우가몬/가오가몬/캅테리몬)는 `community_user_table`로 보존하고 검증. 시간 경과 분기를 자동 실패 결과로 단정하지 말 것.
- 수명은 유한. 끝나면 **진화 / 디지에그화 / 로스트**가 갈릴 수 있다는 위키 규칙을 복원, '모든 개체가 무조건 알로 돌아간다'는 과거 단순화는 폐기.
- 위키 주장: 완전체 이상 또는 10배틀 이상이면 디지에그화 가능; 용량 초과, 질병/부상 방치 등 로스트 가능. 진화 후 용량이 상한 초과면 진화 보류·수명 진행 가능. 수치를 ROM 검증하고 로스트 위험 UI는 게임 편의를 위해 명확히 경고.
- 디지에그를 거치면 일부 요구조건이 줄고 진화 판정 시점이 빨라질 수 있음. 이전 진화 경로/동일 궁극체 반복 등 **진화 기억** 상태 기록. 이전 궁극체로 유도하는 기억 계승은 단순 능력치 보너스만 있는 세대 계승보다 중요. **다른 진화 조건과 충돌하는 판정 우선순위는 검증 필요.**
- 세대 계보, 진화 기록, 대회 기록 유지. 계승 보너스 자체는 확장 요소로 검토하되, 원작의 진화 기억 및 조건 완화와 중복해서 파워 인플레이션 만들지 말 것.
- UI는 '미지의 진화 모드'(기본값: 대상 이름/외형 숨기고 참된 힌트 표시)와 '상세 진화 정보 모드'(대상/조건/달성률 공개)를 설정에서 자유 전환. 정보 공개만 변경, 결과 RNG 조작/결과 선택 불가. 발견한 진화 경로와 이력 기록.

### 2.6 용량/수용량
- 위키: 사육 용량 상한 **200G**, 개체별 필요 G가 다름(일반 약 16~24G, 일부 용족 궁극체 약 32G, 소형 약 18G); 진화 이후 G 증가로 상한 초과 시 진화 불가능. 포획 후 귀환 시 상한 점검, 초과 시 정리 필수. 이 수치는 **원작 기준 검증 후보**.
- **‘초기 3마리’ 제안보다 G 시스템을 우선**하고 시설별 슬롯 점유 수, 개체별 G를 따로 관리. 다중 육각형/보관소가 용량에 어떻게 기여할지는 확장판 결정 보류. 용량 제한을 삭제하면 원작의 종족별 비용/진화 딜레마가 사라지니 기본적으로 유지.

## 3. 위키 자료에서 얻은 원작 검증 후보(ROM에서 대조할 것)
### 3.1 케이지·훈련
- 기본 케이지: 위키상 4칸, 교체 불가, 휴식/신규 포획 수령, 특수 효과 없음.
- 확장 가능 케이지: 원작 가로 5칸→랭크 증가 최대 8칸; 훈련·의료·온천·동물원·목장 등. 케이지 업그레이드 최대 3회라는 서술(원문 정확한 단계 표기 검증).
- 초기 시설 후보: 미니 양호실, 공터, 미니 운동장; 위키 다른 구절의 초기 판매 목록과 구분 필요.
- 미니 체육관: 공격↑/방어↓; 기계↑/벌레풀↓; 빛 내성↑/어둠 내성↓; 수용 2.
- 공터: 방어↑/공격↓; 벌레풀↑/기계↓; 어둠 내성↑/빛 내성↓; 수용 2.
- 미니 운동장: HP↑/TP↓; 짐승↑/용↓; **민첩↑/방어↓ 가능 효과도 위키 주석 [7]에 있음**; 수용 2. 효과 후보 중 하나가 선택되는지 검증.
- 운동장: 능력치 변동 없음(표 기준), 수용 6.
- 미니 화산: 용↑/짐승↓; 공격↑/방어↓; 수용 2.
- 미니 화원: 성↑/암흑↓; 벌레풀↑/기계↓; 수용 2.
- 상승/하락값이 랜덤이라는 설명의 분포, 주기, 케이지 취향 효과는 미확인.

### 3.2 능력치 분리
- 전투/상태: HP, TP(필살기 소비), 공격, 방어, 지능/현명함(특수기 사용 빈도 관련), 민첩함(이동 속도), AP(더위/추위/번개/빛/어둠 내성으로 설명됨; AP의 정확한 인터페이스/각 저항값 형태 검증).
- 진화/육성 전문 수치: 용, 짐승, 기계, 벌레풀, 성, 암흑, 새, 물 등. 전투 스탯과 동일 배열/척도로 취급 금지.
- 건강: 현 HP, 스트레스, 배고픔, 배설물, 부상/질병, 발병 누적횟수, 육성 페널티 누적횟수; 정의·주기 검증.
- 진화: 배틀 횟수, 승/패 및 승률, 디지에그 횟수, 이전 진화 메모리/궁극체 반복, 현 세대/나이/잔여수명, 필요 용량(G).

### 3.3 디지에그 기억 및 예외/주석
- 위키 본문 예시: 메탈가루몬 배틀 20회 vs 지드가루몬 디지에그 2회·배틀 16회 **+ 승률 50% 이상**([11]). 지드가루몬 승률 조건을 충족하지 않으면 메탈가루몬 가능하다는 서술. **우선순위·조건값을 그대로 사실로 확정하지 말고 테스트 케이스로 사용.**
- 질병 진화 예: 올챙몬, 베지몬([12]); 부패 고기 2개 섭취→질병이라는 위키 기술 확인 필요. 디지에그 이후 이전 궁극체로 진화하는 '진화 기억'이 발생해도 도감의 순수 시간 진화 경로로 오기록하지 말 것.
- 용량 초과 원작 동작([13]): 사냥 후 입장 시 용량 정리 유도, 진화 예상 용량이 상한 초과면 진화 불가. 웹판에는 사전 알림 추가 권장.

### 3.4 성격(개체 영속)
- 솔직: 희귀 특수공격 / 빠른 훈련
- 쿨: 특수공격 빈번
- 열혈: 더 큰 피해 / 식량 소비↑
- 대담: 선봉 행동 / 부상↑
- 겁쟁이: 열세 시 도주
- 게으름: 상대가 공격하지 않으면 소극적
- 성급한: 히트 앤 런 / 훈련 산만
- 제멋대로: 호전성↑ / 사회성↓
- 위키 주장: 진화 및 디지에그화에도 성격 고정. 전투 AI, 훈련 빈도, 먹이, 관계 AI에 연결하되 효과 수치는 검증.

### 3.5 포획 및 사냥
- 원작 사냥은 밤 22시 이후 불가(시간 계산 검증). 계절/지역/랭크별 야생 디지몬 테이블.
- 직접 필드에 도구 사용: 로프(디지몬 주변 원 그리기→결박→방향 반대로 끌어 HP 감소/기절 후 포획), 탄환(피해·마비·수면), 먹이 트랩/이동 미끼/독·마비 고기, 폭탄/피해 트랩, 와이어(이동 차단·점착·전기), 레이더, 체커, 메모리, 애널라이저.
- [14] 결박 시 야생 이동 속도가 빨라져 도주 위험. [15] 기본 지급 로프는 유년기용이라 성숙기 포획 불가. [16] 레이더는 주로 성장 단계/종족 기준 대상 선택.
- 소비재는 수량 차감, 장비는 구매 후 실제 장착/세팅해야 적용. 포획 후 용량 검사.

### 3.6 대회 / 타이틀 / 테이머 랭크
- **확정된 확장 방향:** A(원작 대회 구조·보상)를 먼저 충실히 구현하고 **후반에 C(별도 확장 리그)** 추가. 원작 타이틀 매치와 연간 챔피언십을 메인 진행으로 보존.
- 프리 배틀 1:1 / 3:3, 타이틀 매치(참가 조건/기한), 매년 가을 5일 예선→다음 해 본선, 챔피언십 승리 엔딩, 엔딩 이후 고난도 타이틀 콘텐츠(위키 검증 후보).
- 랭크 9: 챔피언십 우승, 랭크 10: 모든 타이틀 획득이라는 위키 설명. 랭크는 진화 가능 단계, 포획 필드, 상점 물품/시설/사냥 도구, 최대 G 및 대회 참가를 관장. **최대 G가 200G로 고정이라는 설명과 '랭크가 최대 용량을 증가시킨다'는 설명 사이의 관계는 조사 필요**.
- [18] 한국어 번역 ‘그라비티 나이츠: 디지에그 24회’는 오역이라는 위키 정정: **일본판 조건은 체급/용량 24G 이상**, 한국판도 24G 이상 개체만 참가. 언어 텍스트 그대로 로직 조건으로 삼지 말 것.
- [19] 랭크 2 이하에서 성숙기 진화도 막힌다는 서술. [20] 랭크 10 링 케이지는 배틀 횟수만 증가시키고 승률은 증가시키지 않음 → 배틀 카운터와 실제 승패 카운터를 분리해야 함.
- 상위 대회 승리로 특수 케이지 지급 가능, 상점의 사육·시설·사냥 상품 해금.
- 후기 확장 리그는 원작 캠페인 완료 후 열리는 별도 콘텐츠로 만들고 원작 랭크·진화 제한과 부작용 없는 독립 진행 상태로 관리.

### 3.7 하루 시간표·NPC 이벤트·돈벌이 (추가 위키, 검증 필요)
- **타이틀 매치 접수 마감: 게임 시간 15:00**. 이미 획득한 타이틀도 재도전 가능하며 보상금 반복 획득 가능하다는 서술. 미수령 타이틀/재도전의 조건 차이, 상금·횟수 제한 검증.
- 15시 이후 또는 타이틀 일정이 없는 날은 프리 배틀 중심의 반복 플레이 가능. **사냥은 22시 이후 불가**라는 앞선 위키 설명과 함께 게임 시계 스케줄러에 반영; 당장 시각만 적어놓고 활동을 막는 임의 규칙을 넣지 말 것.
- 신규 세이브 시 일부 고정 NPC 대전 상대(철수, 영희, 부잣집 아가씨, 오타틱 테이머 등 중 하나)가 정해진다는 위키 설명. 대략 **14~15시 사이 3:3 배틀 도전 쪽지**, NPC 팀은 플레이어 랭크를 따라 성장하고 최종 궁극체 3마리 구성. NPC 이름·발생 조건·상대 고정 규칙은 ROM으로 검증.
- 배틀 종료 시 NPC가 디지몬 양도를 요구하는 이벤트 및 별도 스카우트 제안 존재. **플레이어 소유 디지몬 자동 양도 금지**. 거절과 제시 가격 비교 UI 제공. 보상금/상대 난도 테이블은 원작 데이터 우선.
- 챔피언십 우승 후 이어하기 선택 시 '사장' 도전 이벤트, 이후 **정오 12시 전후 반복 도전**이라는 위키 주장. 팀 후보는 빅토리그레이몬·황제드라몬·듀크몬. 상금은 다른 NPC보다 큼. 승낙/거절 가능, 빈도·팀/이벤트 조건 원작 검증.
- 원작의 초반 자금 부족을 유지하되 반복 대전이 지루해지는 부분은 선택적 **재대전 빠른 등록/일정 안내**, 단 전투를 생략해 공짜 돈을 지급하는 치트식 자동 수급은 기본 비활성.
- 알림 UI에 **다음 타이틀 접수 마감까지 남은 게임 시간**, NPC 초대·사냥 가능 시간, 현재 플레이어 랭크와 해금 예정 시설을 안내.

### 3.8 도감·한국판/해외판 차이·예외·콘텐츠 범위 (추가 위키)
- 해외판은 도감 100% 시 한 개체 직접 조작 해금, 한국 정발판은 도감 완성 무관 SELECT로 순환 직접 조작 가능하다는 위키 설명. **한국 ROM을 기준**, 다른 지역 버전과의 차이를 `regional_rules`로 분리하여 검증.
- 사용자와 이전 합의: **AI 자동 전투가 기본**. 선택적인 원작식 SELECT 직접 조작 모드를 후순위 기능으로 검토. A/B 일반 공격, X/Y 특수기, 샤인그레이몬 등 3스킬 시 A도 스킬이라는 [24] 주석은 입력 맵핑 검증 케이스. 원작에서 입력이 잘 안 먹었다는 경험을 **재현해야 할 버그가 아닌 개선 대상**으로 분류.
- 도감 100% 수집 시 진화로는 얻지 못하는 '꼬끼몬' 포획 필요, 다이나 초원 출현이라는 위키 설명. 포획 전용 개체 여부를 데이터로 구분하여 도감 목표를 실제 달성 가능하게 설계.
- 메탈가루몬의 '그레이스 크로스 프리저' 상성 무시 현상은 원작 버그라는 위키 설명. 전투는 기본적으로 **의도된 상성 계산을 따르는 보정 모드**를 권장하며, 필요하면 `legacy_glitch_mode`로 재현하되 검증 후 제공. 전투 난도/스탯이 원작과 어긋난 이유를 숨기지 말 것.
- 원작의 등장 디지몬은 세이버즈 시대까지이며 일부 파트너/진화 라인이 누락됐다는 위키 평가. **원작 디지몬/진화 루트 기반 구현이 P0~P2 우선**, 팬서비스용 추가 개체(예: 레나몬 진화 라인 확장)는 P3 이후 확장 DB로 원작 데이터와 분리. 기존 자산 없는 추가 개체의 GIF를 임의로 있는 것처럼 주장하지 말 것.
- 번개콩알몬의 X항체 외형 등 **원작에 특이한 모델/스프라이트를 임의로 교체하지 말고** 자산 존재 여부부터 확인.
- 사용자 복사 위키에 섞인 상업 광고·블로그 광고 텍스트는 게임 내용이 아니므로 데이터/명세에서 제외.

### 3.9 주석 [1]~[10] 보강
- [2] 속성/상성이 진화에도 영향을 준다는 주장: 배틀 3속성, 환경 저항, 육성 종족값을 구별하여 진화 규칙의 데이터 참조 확인.
- [3][4] 케이지 성장값은 정해진 후보 중 하나가 랜덤, 1레벨 케이지 기준 약 2~4라는 설명. 확정된 확률·획득량인 듯 코딩하지 말고 참조 시험 케이스로 보관.
- [5] 미니 양호실은 HP 회복과 스트레스 감소, 2마리 초과 또는 성격 충돌 시 스트레스 오히려 상승. 관계 기본형과 연계하되 무작위 과도한 페널티를 넣지 않음.
- [6][7] 공터·미니 운동장의 트레이드오프는 §3.1에 기재. 단 민첩 상승·방어 하락도 미니 운동장 가능 효과로 추가 조사.
- [8] G는 개체별 체급 같은 수용 비용. [9] 페널티 진화는 수명 단축 아닌 질병 등 불리한 진화 루트 유발. [10] 디지에그화 이후 이전 개체 진화 기억 잔존.

### 3.10 새로운 연구 질문 및 충돌 해소
- 위키의 ‘최대 200G’와 ‘테이머 랭크에 따라 최대 사육 용량 상승’의 관계는 **200G가 최대 최종값인지 기본값인지 확인**. 수용량을 200으로 초기에 고정하는 코딩 금지.
- ‘사육장 케이지당 2마리’와 ‘개체별 G 제한’은 별도 자원. 새로운 육각형+보관소가 이를 어떻게 확장할지 임의로 합치지 말 것.
- 원작은 시간 경과/케이지 이동/진화 타이밍이 얽혀 있다. 지속 훈련으로 너무 빨리 진화하는 것을 방지하기 위해 **훈련 틱 속도·시간 배속·세대 기억을 공동 밸런스 테스트**.
- 원작 버그·오역·지역판 차이는 데이터 계층으로 분리하여 `legacy_korean_rom`, `balanced_expansion` 프로파일별 테스트 가능하게 설계. 확장판 편의 기능이 원작 대회·진화 조건을 무의식적으로 바꾸지 않도록 주의.

### 3.11 진행 우선순위 및 캠페인→확장 리그 전환
- 사용자 최종 확정: **A에서 C로 넘어가는 과정**. 원작 타이틀, 챔피언십, 랭크 1~10, NPC 재대전이 첫 단계. 이후 원작 챔피언십 클리어 및 조건 충족을 계기로 별도 확장 리그를 열고 원작 시설·케이지 기능 위에 확장을 쌓는다.
- 확장 리그는 원작 캠페인을 대체하거나 랭크 10 달성을 무효로 해서는 안 된다. 캠페인·도감·타이틀·확장 리그 진행상태 독립 저장.

### 3.12 배틀
- 본래 자동 AI 배틀, 전투 전 3종 성향 설정(일반 공격/지원 공격/특수 공격) 확인. 1:1/3:3 지원, 범위·거리·TP·피격·넉백·상태이상.
- 위키에 따르면 원작은 SELECT로 직접 순서 조작 가능한 예외가 있었음. 이전의 '100% 수동 조작 불가' 서술 수정: 기본은 AI 자동, **선택적 수동 지시/특수기 발동은 원작 동작을 연구한 뒤 제공 여부 결정**. 초기 목표는 자동 전투 우선.
- [23] 슬레이어드라몬 전 공격 추가피해 가능성 / 빅토리그레이몬 일부 드라몬 특효 / 워그레이몬·블랙워그레이몬 특정 필살기만 드라몬 특효라는 위키 주장. 숨겨진 보정 실제 데이터 검증 후 종별/기술별 패시브로 처리. [24] 샤인그레이몬 등 스킬 3개 보유 개체는 A 입력도 스킬 발동할 수 있다는 기술 슬롯 예외 점검.
- [21] '흑 버전도 나온다', [22] '초기 명칭 이글몬'은 주석의 원 본문 문맥이 제공되지 않아 현재 **미연결 주석**, 모델 데이터에 임의 적용 금지.

## 5. Codex 실행 순서 및 산출물
### 단계 P0 — ROM 역분석·원작 행동 명세 (개발 전체의 선행 검증, 단 완료 전에도 작은 수직 슬라이스 병행 가능)
1. ROM 파일 시스템(NitroFS), ARM9/오버레이, 압축 테이블, 포인터 참조 탐색; 케이지 종류/시설 등급/상승·하락 통계, 개체별 G, 종별 진화 대상·조건·수명·성격·기술·랭크 잠금 해제 로직 조사.
2. 위키 제공 수치 및 영상 장면을 재현 가능한 테스트 케이스로 사용. 각 발견에 ROM 파일/주소/바이트 범위/변환 방법/대조 결과를 포함하는 `ROM_DATA_EVIDENCE.md` 작성.
3. 검증된 원작 데이터와 위키만 있는 추정 데이터를 JSON에 분리 저장. 데이터 미확인 시 조용히 가짜 정확한 값을 만들지 말고 `TODO` 또는 명시적인 fallback 데이터 사용.

### 단계 P1 — 핵심 육각형 사육장 구현
1. 단일 콤팩트 육각형 맵+중앙 생활 광장+모서리 시설 슬롯(배치/교체/시설 제한/카메라/터치 hitbox) 구축. 첫 세이브: 알 1개. 기본 육성/회복 전부 이 맵에서 실행 가능.
2. 디지몬 이동 경로, 도착 판정, 시설 예약/동시 사용, 사육장/보관소 구분, 독립 행동 AI, 먹이 배치 및 부패, 회복/스트레스/건강.
3. 훈련 명령 A+B, 선택적 손 도구, 모션 완료별 상승·하락·HP 소모, 자동 중단, 휴식 후 재개, 선택적 미니게임/최고등급 스킵.
4. G 용량·사육장 슬롯·수명·진화 불가 경고 등 게임 상태 관리. 기존 저장 마이그레이션.

### 단계 P2 — 진행 구조
1. 원작 타이틀/프리배틀/챔피언십 스케줄·참가 조건·랭크·상점·시설 해금 구성. 사냥 필드/실시간 도구·포획 구현.
2. 원작 조건 진화/디지에그/진화 기억/로스트/성격. 도감 진화 힌트와 상세 모드.
3. 랭크가 오르면 시설 티어, 해금 슬롯, 새 육각형 연결. 기존 육각형 내 기본 육성 기능 상실 금지.

### 단계 P3 — 전투/확장 콘텐츠/품질
1. GIF 상태/ROM 배경·이펙트 대조, 리얼타임 자동 전투 AI 및 성격·3종 지시·특수기. 수동 지시 여부는 별도 확인.
2. 원작 캠페인 이후 별도 확장 리그. 개체 관계/사회 AI 다듬기, 반복 자동화 장치.
3. PC/Android 및 NDS/확장 뷰로 퀘스트·포획·훈련·진화·저장 리그 회귀 테스트.

### 필수 수락 테스트
- 게임 시각 14:59에는 타이틀 접수 가능/15:00 이후 마감(정확한 경계는 검증); 획득 타이틀 재도전 허용, 보상 처리 및 중복 지급 버그 없는지 확인.
- 초청 NPC·챔피언십 후 사장 NPC 초대, 수락/거절, 고정 NPC 세이브/로드, 랭크별 팀 변화, 알림 시간과 실제 경기 등록 시각 연계 확인.
- 지역판 선택 및 도감 100% 특수 개체 포획, AI 자동 전투 기본/수동 모드 선택 시 조작 맵핑, 메탈가루몬 상성 버그 호환 여부 검증.
- 디지몬 터치→훈련 종류→시설 도착→한 모션 종료 후 HP↓/해당 스탯↑·페널티 스탯↓ → 다음 모션 자동 시작 → 낮은 HP에서 안전 중단.
- 훈련 취소·다른 시설 점유·실수 터치·클릭/드래그 교차·화면 전환에도 이중 보상 또는 상태 증발 없음.
- 미니게임 S등급 획득 후 스킵해도 동일한 시간/HP 소모 및 등급 효과 적용.
- 먹이 배치→이동→먹기, 부패·병력, 의료/휴식 복구, 질병 누적 진화 조건 기록.
- 진화 후 필요 G가 상한 초과라면 진화 차단·경고, 로스트와 디지에그/이전 진화 기억 분기 재현.
- 배틀 횟수만 가산하는 링 효과로 승률이 임의 상승하지 않음; 24G 조건을 디지에그 횟수 24회로 오해하지 않음.
- 대회 우승→테이머 랭크 상승→상점 상품/시설 해금→새 육각형 확장→저장/재불러오기 정상.
- NDS/확장 레이아웃과 모바일 터치 지원, 게임 시간·위치·배치·관계 및 세이브 일관성.

## 6. 아직 합의/검증이 필요한 설계 질문
1. **용량 200G 규칙**을 그대로 유지할지, 다중 육각형/보관소를 통해 추가 G를 해금할지. 원작 랭크별 최대 G가 달라지는지 조사.
2. 원작의 4개 기본 케이지 기능을 새 육각형 맵에서 어떻게 구현할지(기본 생활광장/기본 슬롯으로 환산).
3. 훈련 시설의 상승과 하락 변동치, 랜덤 주기, 3회 강화, 좋아하는 케이지 보정; 지속 훈련 최적 밸런스.
4. 로스트 리스크를 원작 수준으로 유지하되 플레이어가 충분히 이해할 수 있는 경고/UI 제공 방식.
5. 디지에그화 시 능력치/경험치/기억/성격 유지량, 과도한 계승 보너스의 상한.
6. 원작 전투 SELECT 수동 개입을 옵션으로 제공할지(원작 충실도에 중요).
7. 미니게임의 난이도·보너스·S등급 갱신 규칙 및 자동 회복/훈련 반복의 강도.
8. 사육장 구체적인 슬롯 수, 추가 육각형 획득 경로, 다수 육각형 간 디지몬 이동 방식.
9. NPC 도전장 빈도·시각, 타이틀 재대전 리워드, 게임 시간 배속 시 하루 이벤트 중복 발생 방지, 캠페인 완료 후 확장 리그 해금 정확한 조건.
10. 국내판과 해외판의 직접 조작 해금 차이 및 진화/기술 버그 재현 범위.

## 7. 코딩 방식

- 설정/마스터 데이터를 JSON 등으로 데이터 중심 설계, ID 불변·정적 타입 검사 또는 런타임 스키마 검증, 저장 데이터 버전/마이그레이션, 테스트 가능한 결정적 시뮬레이션 타이머.
- 실사용 에셋과 임시 그림을 명확하게 표시하고 원래 애니메이션 GIF 상태를 활용. 프레임·모션 매핑은 기존 ROM 역분석 메모를 참고해 검증.
- 모든 단계의 작업 결과에 코드+재현 절차+실행 검증+미완성 영역 목록+변경 이력 제공. **한 번에 전부 완성했다고 주장하지 않고 작동 가능한 수직 슬라이스부터 구현.**
