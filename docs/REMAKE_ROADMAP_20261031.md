# 디지몬 월드 챔피언십 RE:MAKE — 개발 기준 (2026-10-31)

> **확정된 제품 방향**: 1차 **원작 충실 재현** → 2차 **원작과 분리 가능한 확장판**.
>
> 기존 `kch06667/digichams`의 **최신 `main`을 계속 사용**한다. 새 프로젝트를 만들거나 v1~v9 독립 자유 사육장 ZIP으로 기존 게임을 덮어쓰지 않는다. 이 문서는 향후 의사결정의 기준이다.

## 게임의 중심 재미
- 사냥 지역에서 포획하기 어렵던 디지몬을 잡고;
- 먹이·휴식·훈련으로 능력치를 성장시키며;
- 육성 결과에 따라 원하는 진화 또는 예상 못한 진화를 경험하고;
- **실시간 AI 자동전투**로 대회를 도전하여 보상과 새로운 시설/지역/디지몬을 해금하고;
- 새로운 육성 경로에 다시 도전하는 순환.

월드 크기, 자유 건설, 그래픽 요소의 수는 이 플레이 루프보다 우선하지 않는다.

## Phase 1 — Original Remake (출시 게이트)
**원작 경험을 재현하고 Windows 독립 실행형 PC 게임으로 완성.**

### 사육장 / 케이지
- 원작의 **두 줄 케이지 배치 및 케이지별 환경/역할**을 되살린다. 이는 NDS 기기 상하 두 화면을 그대로 복제한다는 뜻이 아니다.
- PC는 **한 게임 창**에서 케이지 개요 → 선택한 케이지 내부 → 명령/상태를 간결하게 전환한다. 세로로 수많은 실험/설명 창을 쌓지 않는다.
- 디지몬의 케이지 내부 걷기·대기·식사(여러 번 먹기)·훈련(공격 동작)·휴식과 종별 원본 모션을 연결한다.
- 원작에서 시설과 케이지가 주는 육성 효과·해금 조건은 ROM/원작 기록으로 검증한다. 확인 안 된 값은 임시치로 명시하고 원작 일치로 발표하지 않는다.
- v1~v9 자유 배치형 대형 맵은 **보류/실험물**. 헥스 복도나 대형 필드로 다시 돌아가지 않는다.

### 포획 및 진행
- 원작식 탐색·로프를 둘러 묶기·당겨 체력 소진·집어 올리기 동작과 실패 조건 재현.
- 시간/지역/성장에 따른 출현종·포획 난이도·지역 개방은 원작 근거를 추적한다.
- 포획 직후부터 사육장 등록, 보관/교대, 대회 참가까지 동일 개체 ID/세이브를 사용한다.

### 성장 및 진화
- 1차에 해당하는 원작 등장종·진화 경로만 사용한다. 기존 216종 아트/진화 데이터는 **검증 대상이지 검증 완료 보증이 아니다**.
- 능력치, 종족/속성 AP, 육성 실수, 전투 기록, 성장/수명과 원작 진화 분기 우선순위/실패 가능성을 재현한다.
- 진화는 순간 스프라이트 교체가 아니라 명확한 연출/알림/기록이 있고, 예상 밖 결과도 자연스럽게 발생해야 한다.
- 2차 확장 진화는 1차 진행에 섞지 않는다.

### 전투 / 대회
- **상호 독립적으로 이동·공격·회피·피격/넉백·필살기**를 실행하는 AI 자동전투. 한 대씩 번갈아 치는 시연으로 대체 금지.
- 원작 종별 이동/공격/피격/기절/승리 모션과 사운드를 적용하며 다른 모션 오배치 여부를 시각 검증한다.
- 실제 대회 참가 → 승패 정산 → HP/TP/경험/전적/보상/해금 저장 → 사육장 복귀까지 한 세이브로 연결.
- Phaser 실험실은 진입점이 아니며 메인 게임에서 전투 실행. 404·CDN·저장 불일치·Windows 무창 문제를 출시 차단 오류로 취급한다.
- 대회 이름·상대·스케줄·수치가 현재 임시인 부분은 ROM/원작 근거로 대체해야 한다.

### 플랫폼과 배포
- Windows EXE (Phaser 3 + Electron 방향 유지), PC 우선, 실행 시 하나의 게임 창.
- 원작 NDS ROM은 **비공개 분석/검증용**. 공개 GitHub에 ROM/추출 그래픽/개인 세이브를 올리지 않는다. 자산을 포함한 배포는 권리 검토 필요.
- 기존 세이브를 깨지 않는 마이그레이션 및 백업/복원 제공.
- 매 작업마다 ZIP 생성·전송 금지; `main` 기준 작업 브랜치 → 테스트 → PR → 병합.

### Phase 1 수용 기준
1. 새 세이브에서 원작 스타일 포획 → 육성 → 분기 진화 → 대회 AI 전투 → 보상/해금 → 귀환을 실제로 플레이 가능.
2. 분기 진화 성공/의도치 않은 진화 모두 재현되고 원작 근거, 입력값, 우선순위를 기록.
3. 원작 케이지 2줄 개요와 개별 케이지 생활, 훈련·식사 모션을 실제 PC 화면 캡처와 자동/수동 테스트로 확인.
4. 각 배틀 결과가 중복 정산되지 않고 저장/불러오기 후에도 동일하며 404/CDN 의존성 없음.
5. Windows 더블클릭 실행부터 플레이까지 재현 가능한 EXE 확인.
6. 임시 밸런스/원작 미검증 수치가 남으면 항목·출처·제약을 문서화하고 **재현 완료/정식 출시로 주장하지 않는다**.

## Phase 2 — Expansion (Phase 1 완료 후)
- 원작 궁극체의 추가 **궁극체 분기**, 별도 진화 조건과 밸런스.
- **초궁극체** 및 새로운 고난도 육성/진화 체계.
- **캡슐**: 종류·획득·사용·진화 연동 방식을 별도 설계한 뒤 구현 (현 단계에서 임의로 메커니즘 확정 금지).
- 새로운 디지몬·시설·대회·사냥/해금·도감 목표 및 그래픽/모션.
- 동일 엔진에서 **원작 모드와 확장 모드를 분리**해 원작 진화 테이블을 오염시키지 않음.
- v1~v9 자유 배치 실험물은 확장 기능으로도 별도 검토하며 자동 채택하지 않음.

## 현재 코드에 대한 정직한 기준 (2026-10-31)
- `main` README는 웹 기반 프로토타입 v0.23.0의 포획/훈련/진화/대회/자동전투 *부분 구현*을 설명한다.
- 기존 `src/evolution-core.js`는 정확한 ROM 숫자·일부 진화 타이밍이 미검증인 프레임워크.
- 기존 `src/battle-core.js`는 원작 추출 수치가 아닌 확장/임시 전투 규칙을 포함.
- `phaser-lab/index.html`은 현재 실험실 UI이고, 실사용 Windows 전투/세이브 통합은 별도 검증이 필요.
- 최근 #64~#68 개선과 로컬 맵 v1~v9 테스트는 **원작 전체 재현 완료를 증명하지 않는다**.

## 구현 순서와 우선순위
| 순서 | 작업 | 검증 완료 조건 |
|---|---|---|
| P0 | 현재 `main` 실행 및 한 세이브 플레이 루프 기준선 기록 | Windows 실행/포획/사육/전투/진화에서 막힌 위치와 실물 화면을 정확히 재현 |
| P1 | 케이지 2줄 + 개별 생활/명령 화면 (자유 맵 폐기) | 화면 하나로 전환, 디지몬 원작 모션/먹이/훈련/휴식 동작 표시, 기존 세이브 유지 |
| P2 | 진화/육성 원작 기준 검증 및 연출 | 가지별 입력·원작 근거·우선순위·다양한 결과·세이브 회귀 |
| P3 | AI 자동전투/대회 메인 통합 | 404 없는 실시간 AI 전투, 정상 정산과 해금, 멀티 경기 |
| P4 | 포획/케이지/도감/해금 원작 패리티 | 원작 루프 전체와 미검증 목록에 대한 수용 테스트 |
| P5 | Windows EXE·안정성·실기 플레이 | 직접 실행·단일 화면·장시간 플레이·보관 세이브와 회귀 QA |
| P6 | **Phase 2 이후에만** 확장 데이터 추가 | 원작 모드 보호, 새 진화/캡슐 등의 독립 검증 |

## 작업 금지 / 진행 원칙
- 기능 추가 개수로 완료를 평가하지 않는다.
- 원작 영상/ROM을 확인하지 않고 원작 수치를 추측해 확정 수치로 표기하지 않는다.
- 프로토타입 ZIP을 소스 기준으로 삼아 기존 저장 게임의 `main`을 덮지 않는다.
- 새 게임 화면 옆에 별도 실험실/설명창을 계속 붙이는 UI는 허용하지 않는다.
- 타이틀/맵 미술만 다듬느라 핵심 한 개체 육성→진화→대회 루프를 뒤로 미루지 않는다.
