# 오래된 사육장 세이브 — 지도 밖 좌표 복구 (2026-10-28)

## 수정 목표
기존 복도형/초기 테스트 또는 손상된 좌표가 포함된 세이브를 가져오면 디지몬이 지도 밖에 남아 이동·훈련을 완료하지 못할 수 있었다. 최신 육각형 사육장으로 복원할 때 지도 밖 개체는 해금된 시설 중 **가장 가까운 육각 타일의 중앙**으로 안전하게 배치한다.

## 작동 방식
- 정상적인 지도 내 좌표는 전혀 수정하지 않는다.
- 좌표가 유한하지 않거나 도달 가능한 육각형/연결 통로 바깥인 경우에만 복구한다.
- 이동 중/시설 대기/훈련 중이면서 목표가 현재 갈 수 있는 위치라면 목표와 **이미 남은 훈련 시간**을 유지한다. 이미 진행 중인 훈련은 재배치 후 남은 시간부터 재개한다. 새 목표는 임의 생성하지 않는다.
- 목표 자체도 도달할 수 없으면 그 예약 행동은 안전하게 취소한다. 이미 지급한 능력치/Bit/훈련 포인트·소유 디지몬·보관소/세이브 데이터는 건드리지 않는다.
- 좌표 검사는 개체 객체당 **최초 한 번**만 수행한다. 복원된 새 JSON 객체는 새로 검사하므로 매 프레임 반복하는 비용을 피한다.
- 사육장 핵심 로직 `src/farm-core.js`도 HTML 두 벌에 맞춰 자동으로 동기화하도록 `tools/sync-embedded-farm.py`를 확장했다.

## 검사
```bash
node --test tests/farm-offmap-recovery.cjs
node --test tests/farm-navigation.cjs tests/farm-avoidance.cjs
node tests/farm-core.cjs
python3 tools/sync-embedded-farm.py --check
```

GitHub Actions 첫 검증 결과: 신규 복구 테스트 **6/6 통과**, 기존 경로/회피/사육장/대회 Node 회귀 통과. 워크플로의 첫 HTML push는 작업 중 원격 브랜치가 추가 변경되어 *non-fast-forward*로 거절됐고 동기화된 HTML 커밋은 아직 원격에 미반영이었다. 별도 완료 실행으로 재검증 후에만 main 병합한다.

## 제약
- ROM 좌표를 해독한 구현이 아니라 구버전 **웹게임** 세이브 복구 정책이다.
- 정상 좌표의 진화/전투 규칙, 세이브 버전, 훈련 보상 계산은 변경하지 않는다.
- 오래된 저장 데이터에 지도 밖 *먹이/목표 자체*가 있다면 목표가 유효하지 않은 명령만 취소한다. 모든 종류의 손상된 저장 데이터 자동 복구를 보장하지 않는다.
- Android 실기 장시간 검증과 v0.23.2 WebP 그래픽 이식은 아직 별도 단계다.
