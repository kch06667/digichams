# 첫 플레이 테스트 기준과 PR 운영 정책 — 2026-10-31

## 결정
**사용자는 매 PR마다 새 ZIP이나 EXE를 내려받아 시험하지 않는다.** 개발 중 PR의 개별 테스트는 개발 측에서 수행하고, 첫 사용자 플레이는 **Windows EXE로 원작 핵심 루프가 처음부터 끝까지 이어질 때** 한 번 요청한다.

이 일정은 PR 수를 억지로 고정하지 않는다. 작은 변경은 별도 PR로 분리하며, 게이트를 충족하지 못하면 PR이 여러 개 병합되어도 사용자에게 시험을 요청하지 않는다.

### PR 단계 (아래 숫자는 예정된 작업 단계이며 실제 PR 번호가 아님)
- **PR 단계 0 — 계획 확정**: #98, 원작 재현 1차/확장판 2차 분리 및 검사 기준.
- **PR 단계 1 — 원작 사육장 UI**: 원작의 **2줄 케이지 배치**, 케이지 선택 및 생활, 하나의 게임 창에서 화면 전환. 기존 Hex/free-world 실험 UI의 노출을 제거하되 세이브 및 기존 게임 기능은 보존.
- **PR 단계 2 — 육성·진화**: 먹이 여러 입, 원작 훈련 애니메이션과 실제 능력치, 휴식 및 조건에 따른 분기 진화·진화 연출. 원작 값과 임시 값을 구분.
- **PR 단계 3 — 사냥·포획·해금**: 최소 한 원작형 사냥 지역에서 로프 포획 → 같은 개체 ID로 케이지에 등록 → 해금 연결.
- **PR 단계 4 — 자동전투·대회**: 메인 화면에서 동시에 행동하는 AI 자동전투, 넉백·피격·기절·승리 모션, 최소 한 개 대회, 경기 결과/보상/해금 중복 없이 적용.
- **PR 단계 5 — 첫 실행 빌드·세이브 QA**: Windows EXE 더블클릭 → 새 게임 → 포획 → 육성 → 분기 진화 → 대회 → 보상 → 사육장 복귀 → 저장/종료/재개.

## 첫 플레이 테스트의 최소 범위
원작 모든 케이지/지역/216종을 기다리는 게 아니라, **완결된 한 회전**을 먼저 제공한다.

- 하나의 실제로 이용 가능한 기본 케이지와 원작형 2줄 케이지 개요. 나머지 케이지는 원작 해금 조건에 따라 잠금 표시 가능.
- 최소 한 개 포획 지역 및 정상적인 로프 포획/실패.
- 최소 한 계통에서 둘 이상의 가능한 진화 결과와 예상 밖의 결과가 성립할 수 있는 원작 근거 기반 규칙.
- 실제 훈련/식사/휴식 모션과 능력치 변화 및 세이브.
- 적어도 한 개 대회에서 AI 자동전투가 플레이되며 보상과 진척 기록이 반영됨.
- Windows EXE/오프라인 에셋 경로가 정상이고 JS 치명 오류, 404, 무창 문제 없음.
- 재시작 후 동일 개체/상태/보상/해금이 보존되고 보상이 이중 지급되지 않음.

## 개발 측 내부 검사 / 사용자에게 보여줄 자료
- 각 기능 PR: 해당 단위 테스트·브라우저 UI 회귀·저장 호환 확인. 통과한 테스트와 실제로 실행하지 못한 검사를 구분해서 PR에 적는다.
- 시각적 PR: 최소 한 장의 실제 화면 캡처, 필요 시 10~30초 모션 녹화. 원본 ROM/저작권 자산과 개인 세이브를 **공개 GitHub에 업로드하지 않음**.
- 사용자에게 매 PR 설치·실행 지시 금지. PR 완료 여부/위험/다음 작업만 간단히 보고.
- PR 단계 5 이전에는 “게임 완성/지금 플레이해”라고 말하지 않는다.
- 단계 5는 **첫 테스트 빌드**이며 Phase 1 전체 원작 재현 최종 완성/정식 출시와 다르다.
- 첫 테스트 이후 실사용 피드백 수정과 원작의 나머지 케이지·지역·종·대회 패리티를 추가로 완료. Phase 2는 Phase 1 최종 검수 후 착수.
