## 게임 개발과 배포를 구분
- **수정/테스트:** 작은 `src/`, `tools/`, `tests/` 파일을 우선 읽고 수정한다. 6–20 MB HTML 전체를 채팅에 붙여 넣거나 매 턴 반복 분석하지 않는다.
- **개발용 실행:** `npm run dev:build` 또는 `node tools/build-dev-page.cjs` 실행 후 `python3 -m http.server 8000 --bind 127.0.0.1`. 브라우저에서 `http://127.0.0.1:8000/index.dev.html` 열기. `index.dev.html` 및 `.dev-generated/`은 자동 생성되며 Git 추적에서 제외한다.
- **로직 검증:** `npm run test:dev`로 JS/CSS 추출 안정성 검사. 변경된 시스템에 맞는 기존 Node/Playwright 테스트도 실행한다.
- **실제 배포/호환성:** 기존 `index.html`과 `standalone.html`은 유지한다. 인라인 소스 동기화와 저장/불러오기·터치 테스트가 통과한 시점에만 배포본을 갱신한다.
- **ZIP:** 매 업데이트에 자동으로 전체 ZIP을 만들거나 사용자에게 보내지 않는다. 사용자가 요청하거나 릴리스/백업이 필요한 시점에만 만든다.
- **기록:** 의미 있는 작업 단위마다 커밋, 변경 요약, 실행한 검사 결과, 미검증 사항, 다음 할 일을 `CONTINUE_HERE.md` 또는 별도 짧은 개발 기록에 남긴다. 성공하지 않은 테스트를 통과로 표기하지 않는다.

## 모듈화의 현재 한계
`build-dev-page.cjs`는 현재 `index.html`의 인라인 script/style을 *내용 변경 없이* 로컬 외부 파일로 추출하는 안전한 **개발용 진입점 생성기**다. 리팩터링 완료나 모든 게임 로직의 소스 단일화가 아니다. 소스 `src/*.js`와 인라인 HTML 내용이 어긋나면 기존 작업 지침대로 의도와 호환성을 검토한 뒤 동기화한다. 8,000개 이상의 GIF를 동시 로드하지 않도록 하는 런타임 최적화는 별도 실측/개선 과제다.
