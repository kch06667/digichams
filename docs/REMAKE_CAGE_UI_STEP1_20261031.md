# 리메이크 Phase 1 / PR 단계 1 — PC 케이지 2줄 선택 화면 (2026-10-31)

## 목적
원작을 즐기고 싶다는 사용자 목표를 기준으로, 기존의 육각형 복도 지도·공원식 자유 사육장 대신 **케이지 목록 → 선택한 공간에서 돌보기/훈련하기** 흐름을 우선 제공한다. 별도의 게임/세이브/스탯을 만들지 않는다.

## 이번 작업
- **PC 마우스/폭 900px 이상에서만** 단일 화면형 사육장 케이지 목록을 보여준다.
- **2행 × 6열**: 기존 `DCCages.CAGES`의 11개 종족 AP 훈련 시설 + 기본 사육장 1개를 표시. 목록 수와 명칭은 현재 게임의 실제 데이터에서 가져온다. **이 배열이 원작 NDS의 정확한 케이지 슬롯 개수/순서라는 주장은 하지 않는다.**
- 잠긴 케이지는 해금 조건과 Bit 비용을 보여준다. 선택하면 기존 `#hexCageSelect`에 반영하고, 실제 `#hexCageBuy`/`#hexCageTrain` 버튼을 이용해 기존 게임 로직을 실행한다.
- 기본 생활 공간은 기존 `#farmViewport`와 원래 디지몬·먹이·훈련·휴식 DOM을 그대로 연다. 화면에서는 옛 육각형 경계/연결선만 가린다. **기존 이동/충돌 시뮬레이션은 여전히 hex 엔진이 처리한다.**
- 원래 NDS 상하 2화면 셸이 PC에서 활성화돼 있으면 기존 `#wideMode` UI 버튼으로 단일 넓은 게임 화면을 선택한다. 별도의 화면 모드 저장 포맷은 추가하지 않는다.
- `src/pc-playability-guide.js`에서 프로덕션 PC 전용으로 새 `src/remake-cage-view.js`를 로드. 미지원/터치 기기에는 적용 안 함.
- 게임 코드 `index.html`, `standalone.html`, `src/farm-core.js`, `src/hex-farm-ui.js`, 포획/진화/대회/세이브 데이터 구조는 변경하지 않음.

## 검증
- `python tests/remake-cage-view-browser.py`: synthetic 로스터/해금/시설을 사용하는 Chromium PC/모바일 회귀. 로컬 해당 테스트 구성과 함께 별도의 **사용자 제공 v0.23.2 HTML 기반 Playwright 검사**에서 케이지 12개, 두 줄, 기본 공간/잠금 시설, 원래 훈련 UI, 개체 ID/재화/해금 저장 불변, 모바일 비적용, JS 예외 0을 확인했다.
- **제약**: 현재 작업 환경의 localhost 브라우저 내비게이션이 정책상 차단돼 `page.set_content`로 구버전 HTML을 검증했다. 최신 원격 `main`의 실제 HTTP 렌더/Windows 실기 실행 결과는 아직 확보하지 못했다. 일부 로컬 이미지가 로딩되지 않은 상태에서는 배경의 미술적 완성도를 평가할 수 없다.
- 원작 캡슐/추가 궁극체/초궁극체 및 원작 케이지 전부의 정확한 그래픽/규칙은 이번 PR 범위 밖. 첫 사용자 플레이 시점까지 다운로드/테스트 요청하지 않는다.
