# 디지몬 챔피언십 웹 이식 프로젝트 — 장기 작업 지시서

## 목적
NDS 《디지몬 챔피언십》의 화면과 자산을 최대한 그대로 살리면서 PC/Android 브라우저에서 실행 가능한 독립 게임으로 단계적으로 완성한다. 기존 v0.14의 결과물을 개선하되 동작하는 기능을 회귀시키지 않는다. 원작 복제에 사용되는 자료는 사용자가 직접 제공한 ROM과 GIF 패키지 및 플레이 영상이다. 원본 ROM 코드로 확인한 규칙과 웹판에서 추정·재구현한 규칙을 명확히 분리한다.

## 필수 입력
- `digimon_championship_recreation_v0.14.html` 또는 `digimon_championship_recreation_v0.14_full_site.zip` (현재 동작하는 기준 버전)
- `디지몬 챔피언쉽(K).nds` (ROM)
- `DigimonWorldChampionshipSprites.zip` (디지몬별 40 GIF 애니메이션)
- `디지몬 챔피언쉽 5일차.mp4` (사육장·대회·진화 참고)
- `Wargreymon vs Black Wargreymon (digimon world championship).mp4` (전투 참고)

## 우선순위 / 인수 조건

### P0: 사육장 및 진행도 시스템
1. 최초 새 세이브: **기본 복도 한 구역만 소유**. 다른 훈련 에리어·휴식실·치료실·야외 에리어는 잠긴 상태로 지도에서 표시한다.
2. 원작처럼 좌우로 길게 연결된 맵을 횡스크롤 탐색하며, 여러 디지몬은 열려 있는 구역 사이를 이동할 수 있다. PC/휴대폰/2화면 모드를 모두 지원.
3. 시설 해금은 **재화, 사육사 등급, 승수/일자/기타 조건, 연결 시설 선행 구매**를 검사한다. 잠긴 시설을 누르면 각 조건을 명료하게 보여준다.
4. 실제 구매 시에만 재화를 차감하고 즉시 해금, 저장/재시작 후에도 유지한다. 중복 구매, 음수 금액, 승리 보상 중복 지급 금지.
5. 훈련·일자 진행·대회 보상으로 재화를 획득한다. 현재 임시 값은 기초훈련 +20 Bit, 하루 +35 Bit, 대회 승리 +180 Bit. 게임 밸런스 규칙은 데이터 파일로 관리. 실제 ROM 수치가 확인되면 차이를 표로 작성.
6. 진화/전투/포획/도감과 기존 저장 데이터가 깨지지 않아야 한다. 세이브 데이터 버전 및 마이그레이션 마련.
7. 육성 공간의 ROM 배경/타일을 가능한 한 재사용하고, ROM에서 직접 복원하지 못한 합성 요소는 명시한다.

### P1: 시설 행동과 메뉴 원작 재현
1. 영상의 시간대별 키프레임과 ROM 훈련·사육 UI 그래픽을 대조해 화면 배치 복원.
2. 훈련/휴식/치료/먹이 메뉴를 실제 사육장 시설과 연결하고, 대상 디지몬 선택·행동 GIF 매핑 정확히 적용.
3. 행동 발생 시 사육장 스프라이트도 0/1 idle, 2 walk, 13 sleep, 14 eat, 28 happy, 32 train 등 해당 GIF 재생.
4. 원작의 등급·시설·메뉴·진화 조건을 역분석할 수 있는 파일을 추가 조사하되, 검증되지 않은 사실을 주장하지 않는다.

### P2: 전투 마지막 완성 작업
1. v0.10~v0.13의 2D AI 흐름과 원작 영상의 접근→근접공격→긴 이탈→재접근을 유지.
2. **넉백을 지금보다 강하게**, 긴 피격 동작과 잠깐의 경직을 추가하되 강도·시간을 설정값으로 빼서 조정 가능하게 할 것.
3. 이동·공격 방향에 맞춰 스프라이트 좌우 반전. 필살기 종류마다 근접/원거리 타입과 기술명 배너·충전·이펙트 차별화.
4. 원본 ROM 이펙트 중 실사용 가능한 데이터를 복원해 보지만, 실패해도 임시 이펙트라고 명확히 구분.
5. 1대1/3대3 모두 2분 정도의 AI 전투를 실제 브라우저에서 실행 테스트하고 충돌·무한 정지·캐릭터 이탈 여부 검사.

### P3: 그래픽 / 전체 종
1. ZIP의 216종, 각 40개 GIF 상태 번호에 대한 인덱스·동작 메타데이터 정리.
2. 마리별 이름·진화·스탯은 실데이터가 확인된 것과 임시값 분리.
3. 0~39 상태 매핑: 0 idle, 1 blink, 2 walk, 3 run, 4 surprised, 5 hit, 6 jump/hit 후보, 7~10 attacks, 13 sleep, 14 eat, 16~25 tied, 28 happy, 29 angry, 30 cheer, 31/34 guard, 32 train, 37 KO, 38 jump/hit 후보, 27/36/39 미상. 6과 38을 승리 점프로 임의 확정하지 말 것.
4. 테스트용 데이터만 있는 종과 정식 플레이 가능한 종을 정확하게 구분.

## 기술 품질 기준
- 기존 거대한 HTML 파일을 모듈 구조(게임 상태, 시설 데이터, AI, UI, 자산 로더)로 점진적으로 분리. 단일 HTML 배포판도 병행 제공.
- 화상/상태 코드의 동일 ID 중복 또는 스타일 충돌 방지.
- 모바일 가로 스크롤과 NDS/확장 전환 시 선택한 구역이 카메라 중앙을 유지.
- 새 게임/이전 세이브 불러오기/시설 해금/저장/새로고침/전투 보상, 모바일과 데스크톱 동작에 대한 자동 테스트 구현.
- 실행 가능한 산출물 `index.html` 또는 ZIP, 변경 이력, 실험적 규칙 목록, 테스트 스크린샷과 QA 결과 포함.
- 아직 확인되지 않은 원작 데이터는 문서화한 TODO로 남기며 원본 복원을 완료했다고 주장하지 않을 것.

## 즉시 작업 시작점
v0.14에 이미 있는 7개 구역의 가로 지도와 잠금/구매 시스템을 기반으로, ROM의 사육장 코리더 타일을 더 자연스럽게 연결하고 상하 2화면 UI에 맞게 정리하라. 그 뒤 세이브 마이그레이션·경제/등급 밸런싱·시설별 행동 UI 순서로 이어가라. 필요한 파일이 없으면 그 사실을 명시하고 이미 제공된 파일 범위에서 최대한 진행하라.
